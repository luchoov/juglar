juglar / explorables / 05

Warps and fractals

Every one of Juglar's twelve scenes runs on the same loop (explorable 03): each frame starts as a slightly changed copy of the last, and a little paint goes on top. What makes the scenes so different is mostly one small function, the warp, which tells each pixel where its old paint comes from. This page plays with a few warps, then with two that turn the loop into a machine for fractals. The JavaScript mirrors crates/render/src/feedback.wgsl, composite.wgsl and the scenes' shaders in crates/render/src/scene/; the theory is in note 10.

01Where does the paint come from?

Each frame, every pixel asks one question: where was my paint a moment ago? (Asking it backwards, from the new pixel, leaves no holes; explorable 03 shows why.) The answer is the warp. Below, three soft lights circle the middle and leave trails, and you choose the warp the trails live in. The lights are the same in every case; only the warp changes.

A tunnel (zoom and turn) sends every trail outward along a spiral. A fold takes each pixel's paint from the matching point of one wedge, reflected, so after a few frames everything is mirrored six ways. Rings that turn against each other shear trails into kinks and whorls. Paint running down takes each pixel's paint from a little above it, faster in some columns than others. A lens magnifies or shrinks what is under it, and since the loop repeats that every frame, a magnifying lens keeps blowing paint out of its middle and a shrinking one keeps swallowing it. Each is the warp of the scene named in the menu, with the same lines of code.

Optional, for the curious: Vortex's warp (crates/render/src/scene/vortex.wgsl) 
fn warp(p: vec2f, q: vec2f) -> vec2f {
    let r = length(q);
    let pattern = knob(3u);
    let turn = sin(r * 9.0 + pattern) * 0.7 + sin(r * 4.0 - 1.3 * pattern) * 0.3;
    let edge = 1.0 - smoothstep(0.4, 0.9, r);
    let turned = rotate(q, knob(0u) * turn * edge);
    let push = 1.0 - knob(1u) * edge * sin(r * 14.0 - knob(2u));
    return turned * push;
}

q is where the usual zoom and turn already point; the scene moves it further. Every scene's warp has this shape, and the JavaScript on this page has one function per scene with the same lines.

02A fractal, one step per frame

A Julia set comes from one rule. Take a point z of the plane, square it and add a fixed number c, then do it again, and again. (Points are complex numbers here: squaring doubles a point's angle around the middle and squares its distance from it.) Some points fly off to infinity, others stay near the middle forever; the border between the two is the fractal. The usual way to draw one repeats the rule dozens or hundreds of times for every pixel, every frame.

Julia repeats it once. Its warp is the rule: each pixel takes its old paint from z² + c. Pixels whose next step leaves the picture get fresh paint. A pixel one step from leaving shows that paint one frame later; a pixel two steps away, two frames later; and so on. And paint moves along the palette with every step, so the steps come out as bands of color. Points that never escape never get paint: the black heart of the set.

Press Start from black and watch: the outside lights up first, then each band, one step per frame, closing in on the set. After about a hundred frames the picture has settled, and the loop has done for every pixel what the usual way does: a hundred steps. It spread them over a hundred frames, one step each. Once settled, it keeps up as c moves, since each new frame is one more step of the new rule over a picture that was nearly right already. In Juglar this costs 0.24 to 0.25 ms of GPU time per frame at 960×540, about what a tunnel costs (Tide: 0.22 ms).

The ring outside shows the other half of the trick. Anything painted into the picture is copied back through the steps too: the ring comes back as nested, ever smaller, ever more crinkled copies hugging the fractal's edge. In the scene the ring is drawn by the waveform, so the music's shape is copied into the fractal.

Optional, for the curious: Julia's warp and paint (crates/render/src/scene/julia.wgsl) 
fn julia_step(z: vec2f) -> vec2f {
    return vec2f(z.x * z.x - z.y * z.y, 2.0 * z.x * z.y) + vec2f(knob(0u), knob(1u));
}

fn warp(p: vec2f, q: vec2f) -> vec2f {
    let scale = knob(2u);
    return julia_step(q * scale) / scale;
}

fn sources(p: vec2f, pixel: f32) -> vec3f {
    let scale = knob(2u);
    let z = p * scale;
    let next = julia_step(z);
    let escape = smoothstep(-0.1, 0.0, length(next) - 0.49 * scale);
    let leaving = 0.12 * sin(2.0 * atan2(next.y, next.x));
    let ring = julia_ring(z, pixel * scale);
    let coverage = max(escape, ring);
    let share = ring / max(coverage, 1e-4);
    let ink = mix(knob(6u), knob(7u), share) * coverage;
    return vec3f(coverage, ink, ink * mix(leaving, 0.5, share));
}

A point counts as escaped when its next step leaves the circle that fits in the picture (of radius 1.52 in the set's units). No point beyond (1 + √(1 + 4|c|)) / 2 ever comes back, which is 1.52 for the scene's usual c; for c further out, like the dendrite's, a few points between 1.52 and that radius may be painted as escaped although they would have stayed.

03Copies of copies

Crystal uses the same trick with a different step: turn the picture, fold it into five mirrored wedges, move it out from the middle, enlarge. Read backwards, as a warp is, that puts a small copy of the whole old picture in each of five places around a ring. The next frame copies the copies. A soft ring in the middle becomes five rings, then twenty-five smaller ones, then a hundred and twenty-five, a snowflake that is a fractal: what mathematicians call an iterated function system, run by the loop one generation per frame.

Turn the turn slowly and watch the rim: every generation is turned once more than the one inside it, so the smallest copies, at the edge, swing furthest. In the scene that is where the flash limiter first had to step in, when the turn moved twice as fast as it does now. Raise the fade toward 0.95 and the deep generations fill the crystal with a carpet of tiny rings; lower it and only a few generations show.

Optional, for the curious: Crystal's warp (crates/render/src/scene/crystal.wgsl) 
fn crystal_fold(p: vec2f, wedges: f32) -> vec2f {
    let wedge = TAU / wedges;
    var angle = atan2(p.y, p.x);
    angle = angle - wedge * floor(angle / wedge);
    angle = abs(angle - 0.5 * wedge);
    return vec2f(cos(angle), sin(angle)) * length(p);
}

fn warp(p: vec2f, q: vec2f) -> vec2f {
    let folded = crystal_fold(rotate(q, knob(0u)), knob(1u));
    return (folded - vec2f(knob(2u), 0.0)) * knob(3u);
}

04Wild, but not strobing

Fractals are full of small, fast detail, which is exactly what a screen must not flash. The rule (explorable 04) counts a swing of 0.1 in brightness, back and forth, and allows four such swings in any second, anywhere. Bands of color sliding past a point make its brightness rise and fall once per band, so three things keep these scenes inside the rule. Their parameters move slowly, so few bands pass a point each second. Deep steps and generations are faded, and faint paint swings less. And their palettes keep a narrow range of brightness: the colors differ a lot in hue, much less in light.

At full ink both palettes swing by more than 0.1, so bands passing faster than two per second would break the rule with either; the limiter would hold them back. With less ink, Julia's palette drops below the 0.1 that counts much sooner than Kaleido's (below about 0.45 of ink, against 0.22). That is why its deep bands, the thinnest and fastest, stay calm.
