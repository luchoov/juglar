How Juglar hears

Before Juglar can draw anything, it has to turn sound into a handful of numbers that move like music. This page runs the same algorithms as Juglar's dsp crate, so you can poke at them.

01A sound is a sum of waves

Your speakers play one long list of numbers, 48,000 per second. That list can always be described as several sine waves of different frequencies added together. Below are three tones and some noise. The graph shows the 2048 samples Juglar analyzes at once, about 43 milliseconds.

02The FFT finds the waves

The Fourier transform asks, for every frequency, “how much of this is in the signal?” It multiplies the samples by a wave of that frequency and adds up the result: matching waves add up, others cancel out. The fast Fourier transform gets the same answer for all 1025 frequencies in about 22,000 steps instead of 4 million. Move the tones above and watch their peaks move here.

Optional, for the curious: the real Rust code for one stage (crates/dsp/src/fft.rs) 
// Merge pairs of half-size transforms into full-size ones: sizes 2, 4, ..., n.
let mut size = 2;
while size <= self.n {
    let half = size / 2;
    let stride = self.n / size;
    for block in buf.chunks_exact_mut(size) {
        let (evens, odds) = block.split_at_mut(half);
        for (k, (even, odd)) in evens.iter_mut().zip(odds.iter_mut()).enumerate() {
            let twisted = *odd * self.twiddles[k * stride];
            *odd = *even - twisted;
            *even = *even + twisted;
        }
    }
    size *= 2;
}

Each pass doubles the size of the transforms it has built. After log2(n) passes, the whole buffer is the spectrum.

03Why the edges have to fade

The FFT assumes its 2048 samples repeat forever. Real audio almost never ends where it started, so the imaginary repetition has a jump, and a jump contains every frequency. Turn the Hann window off above: each clean peak smears into a wide skirt that buries quiet sounds. Fading the edges in and out removes the jump. The price is a slightly wider peak.

Now change the FFT size. A bigger window separates frequencies better (look at two low tones close together), but it averages over more time, so the visuals would react later. That trade-off can't be escaped; Juglar uses 2048.

04Thirty-two bands, the way we hear

We hear pitch by ratio: 100 to 200 Hz and 1000 to 2000 Hz both sound like one octave. So Juglar groups the bins into 32 bands that are evenly spaced on a log axis. Look at the leftmost bars: below 100 Hz there are only a few bins to share among several bands, so neighbors show the same height. Switch to 4096 and they separate.

05Envelopes: jump, then breathe

Even after all that, the level changes nervously from one frame to the next. Visuals driven directly by it tremble. An envelope follower smooths it unevenly: it rises fast (attack) and falls slowly (release). Below is a drum pattern at 120 BPM. Make the release very short and the envelope copies the jitter; make it long and the beats blur together.

Optional, for the curious: the real Rust code (crates/dsp/src/smoothing.rs) 
pub fn update(&mut self, input: f32, dt: f32) -> f32 {
    let tau = if input > self.value { self.attack } else { self.release };
    // Exact exponential smoothing for this `dt`, not the frame-rate
    // dependent `value += (input - value) * k`.
    let k = if tau > 0.0 { 1.0 - (-dt / tau).exp() } else { 1.0 };
    self.value += (input - self.value) * k;
    self.value
}

Using the real elapsed time dt makes the smoothing look the same at 30, 60 or 144 frames per second.
